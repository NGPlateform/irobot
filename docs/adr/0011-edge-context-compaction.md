# ADR-011: 边缘上下文压缩为硬约束；云/边共用同一动作协议

- 状态：Accepted
- 日期：2026-07-30
- 决策人：技术负责人 + Agent 工程师
- 相关评审人：Agent + 平台

## 背景

Agent Runtime 在部分场景需运行于算力受限的边缘设备（离线或弱连接）。在云端，上下文压缩（工具结果配对、上下文预算、主动压缩）是节省成本的优化；在边缘，短上下文窗口和小模型使其成为能否运行的硬约束。若两种形态使用不同的动作语义或工具协议，会产生两套需分别验证的物理动作路径，违背单一权威路径原则。

## 决策

- 边缘形态下，上下文压缩视为硬约束而非可选优化；Agent Runtime 的工具结果配对、上下文预算和主动压缩必须在此形态同样成立。
- 云端与边缘共用同一 Tool Schema 和动作提案协议（Action Envelope），只切换模型与预算参数，不改动作语义。

## 后果

- 正面：物理动作路径只有一条，云/边差异收敛到"模型 + 预算"两个参数；安全校验、协议契约、测试全部复用。
- 负面 / 代价：Agent Runtime 从一开始就要按"可在小窗口运行"设计，早期实现约束更强。
- 安全影响：正向。避免了云/边两套动作语义各自演化、其一漏掉安全校验的风险。

## 备选方案

- 边缘用独立的精简动作协议：实现更快，但产生第二条物理动作路径，长期是安全与维护负债，否决。
